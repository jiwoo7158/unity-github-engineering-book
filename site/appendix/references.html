검증이 필요한 항목#

  • GitHub와 Unity의 요금·스토리지·Actions 사용량·Pages 공개 범위는 변동 가능성이 있으므로 최신 가격표와 계정 상태를 확인해야 한다.
  • Unity 에디터의 설치 경로, 빌드 API, 테스트 CLI, 라이선스 인증은 버전별로 다르다. 사용 중인 Unity 버전의 문서를 우선한다.
  • GitHub Projects의 필드·권한·UI는 저장소/조직 권한과 기능 출시 상태에 따라 달라질 수 있다.
  • 각 장의 YAML 및 C# 예시는 교육용이며 실제 사용자 환경에서 실행 검증된 완성 프로젝트는 아니다. 로컬 실습→로그 분석→작업 환경에 맞춘 조정을 전제로 한다.

소프트웨어공학 관점의 원칙#

본서가 사용하는 요구사항 → 구현 → 리뷰 → 테스트 → 빌드 → 배포는 개발 과정의 추적성과 재현성을 높이는 실무 흐름이다. GitHub 자체가 게임 기획의 재미, 일정의 현실성, 팀원의 동기, 출시 품질을 자동으로 보증한다는 의미는 아니다. 게임 특유의 플레이 경험 검증은 별도 설계·관찰·실험이 필요하다.

이 책에서 확인하지 못한 부분#

이 문서 패키지를 생성하는 환경에는 사용자의 GitHub 저장소 관리자 권한과 정확한 Unity 프로젝트/라이선스 정보가 없다. 따라서 실제 GitHub 프로젝트 화면 설정, GitHub Actions 실행 비용, Unity 빌드 성공, 스토어 배포 성공을 실측 검증하지 않았다. YAML과 코드 예제는 학습용 구성으로 제공하며 테스트 프로젝트에 적용해 검증해야 한다.
