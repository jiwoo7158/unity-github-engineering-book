# 부록 C. 복사해 사용할 수 있는 템플릿

본문의 개념을 실제 저장소에 옮길 때 참고하는 **최소 초안**이다. 모든 필드를 채워야 한다는 규칙이 아니라 팀이 무엇을 합의해야 할지 놓치지 않도록 돕는 출발점이다.

## 1. Repository README

```markdown
# 게임명 / 코드명

## 프로젝트 개요
- 장르:
- 핵심 경험:
- 플랫폼:
- 개발 상태:

## 개발 환경
- Unity Editor 버전:
- 타깃 플랫폼 모듈:
- Git LFS 필요 여부:
- 핵심 패키지:

## 시작 방법
1. 저장소 Clone
2. Git LFS 확인
3. Unity Hub에서 프로젝트 열기
4. 샘플 씬 실행

## 작업 절차
- 담당 업무: GitHub Projects
- 상세 요구사항: GitHub Issues
- 코드 리뷰: Pull Requests
- 빌드 확인: GitHub Actions

## 문서
- 게임 기획 원본:
- 아키텍처:
- QA/빌드:
- 팀 연락:
```


```markdown
## 버전 / Git Tag / Commit SHA

## 대상 플랫폼과 기준 사양

## 자동 검사 결과
- 테스트:
- 빌드:

## 실제 게임 확인
- [ ] 시작/종료
- [ ] 저장/로드
- [ ] 씬 전환
- [ ] 게임패드/화면 설정
- [ ] 주요 프레임/메모리 기준
- [ ] 심각 버그 및 알려진 문제

## 라이선스 및 배포 검증

## 담당자 승인과 근거

## 문제 발생 시 핫픽스/복구 방법
```

## 9. 반복적인 주간 운영 기록

```markdown
## 이번 개발 목표

## 실제 완료된 게임 빌드/작업

## 막힌 작업과 필요한 지원

## 새로 발견한 주요 위험

## 테스트에서 알게 된 점

## 다음 주 우선순위 및 범위 변경
```

이 문서의 템플릿들은 **팀원의 행동을 돕는 최소 가이드**로 사용한다. 체크박스 수를 늘리는 것이 아니라 기록한 정보가 다음 행동에 실제로 쓰이는지를 기준으로 유지·축소해야 한다.


### AI 작업 검토 체크

```markdown
- [ ] 기존 프로젝트 코드와 유사 구현 검색
- [ ] 요구사항·관련 시스템·변경 범위 이해
- [ ] 예상 밖 파일 생성/수정 이유 확인
- [ ] 테스트 수행 결과와 미수행 항목 분리
- [ ] 프로젝트 설계 결정(ADR) 위반 여부 확인
- [ ] 사람이 주요 구현과 실패 시 복구 방법 설명 가능
```
